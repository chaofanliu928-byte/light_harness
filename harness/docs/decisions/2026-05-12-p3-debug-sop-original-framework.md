## 原文(原样保存)

### 三条核心原理

1. **解决问题最重要的,是完美定义出问题。** 当问题模糊时,人会一头乱麻;问题被精确定义出来的那一刻,难度就从"无从下手的难"变成"知道怎么下手的难"。SOP 前半段(步骤 1–3)权重远大于后半段,就是这个原理的体现 — 把功夫花在定义上,方案往往会自己浮现。

2. **通过扮演资深领域研究员来生成方案,这是提示词的能力。** 大模型在中性提示下倾向于罗列已知信息;切换到"资深研究员"视角能激活它的评估、权衡、综合模式,输出质量显著提升。但要约束在检索回的内容上,避免角色扮演下"自信地胡说"的失败模式。

3. **完整规范的 debug 流程,效能巨大。** 一个流程化、有反向边、有反馈环的 SOP,让智能体(和人)不跳步、不被沉没成本绑架、不重复踩坑。每走一次都积累知识库 — 这是"越用越聪明"的复利所在。

### 启动输入

- **轻上下文** — 项目目的、服务对象、技术栈大盘 — SOP 启动时即载入,是解读现象的必需输入。
- **重上下文** — 团队偏好、性能约束、运维边界、历史决策 — 留到第 6 步加载,避免提前污染假设阶段。

### SOP 流程

1. **接收问题现象。** 收集报错信息、复现路径、相关日志、用户对症状的描述。**只记录,不下判断**。

2. **形成假设 ✱。** 基于现象 + 轻上下文,明确输出"假设问题是 X,由 Y 触发,表现为 Z,置信度低 / 中 / 高"。信息不足时进入询问点,用结构化问题补充。

3. **复现验证。** 目标是**用证据检验假设,而不是验证假设**。如果复现结果与假设不符,回到步骤 2 重新形成假设 — 这是**反向边,必须显式回退**。

4. **已知问题判断 ✱。** 对照知识库判断:这是已知问题的新实例,还是真正的新问题?模糊匹配时进入询问点确认。已知 → 5a;新问题 → 5b。

5a. **检索同行业方案 + 资深研究员综合(已知分支)。** 分两步走:
   - (1) 智能体主动检索同行业资深工作者的稳定解决方案 — 通过文档、技术博客、issue 跟踪、社区讨论等渠道
   - (2) 切换到"资深研究员"视角,对检索到的方案做综合分析 — 适用前提、潜在副作用、与重上下文的匹配度 — 输出推荐方案 + 适用条件 + 已知风险
   - **隐性反向边**:如果方案在步骤 6 适配验证不过,回退到 5b 重新做根因分析(说明步骤 4 判断错了)。

5b. **多视角根因分析(新问题分支)。** 从代码层、系统层、设计层多角度看同一个问题。**停止条件:「消除这个原因后,问题会不会以变形方式回来?」答"会"继续挖;答"不会"即根因。**

6. **方案设计与验证 ✱。** 加载重上下文。多个候选时进入询问点,用拆解 + 取舍方式问。**验证标准:问题不再以同样形式或变形方式出现**。

7. **沉淀至知识库。** 记录现象、假设演化路径(含被推翻的中间假设)、根因、方案、验证结果。这条记录成为下次步骤 4 的匹配输入 — **反馈环**就在这里。

### 横切原则(适用于所有标 ✱ 步骤)

向用户询问时遵循"设计过的问题"四标准:**拆到原子选择、带取舍说明、嵌入已有上下文、必要时才问。**

## 关键独有价值(harness 应保留,不被稀释)

后续展开 spec 时,以下 5 条是 P3 与传统 debug SOP 的核心区分,**必须保留**:

1. **"完美定义问题 > 解决问题"** — SOP 前半段(1-3 步)权重 >> 后半段
2. **轻 / 重上下文分层** — 防止重上下文污染假设阶段
3. **"用证据检验假设" vs "验证假设"** — Popper 式科学方法论(步骤 3)
4. **已知 / 新问题分流 + 资深研究员视角** — 步骤 4 + 5a 的核心区分
5. **询问点四标准** — 横切原则,适用于 P3 之外的所有 harness 流程
