## 问题

meta 治理比正常治理多一层:两套 finishing(M1/M5)、两套审查规则、scope 分流机器(M3 三表↔M17 conf)、三个 skip 字段、两套证据档位。实证:每个仓库实际只活在一条轨上(自仓库几乎全 meta、下游零 meta),双轨复杂度两边都付,收益只在理论上的 mixed;开场对账只核 meta scope,凭证制度不完整。

## 决定(乙案 + 第一性重推四件)

**三件套**:finishing-rules(唯一收口,原 M1 步骤并入)/ review-rules(唯一审查,维度选择表:代码|设计|治理→维度集+力度;治理类=bootstrap 4 维强制+触点完整性按需+N 弹性)/ **credentials-rules.md(新件:凭证与对账——audit 产物规范/失效规则/对账规程/凭证要求表人读版/证据档位参数化)** + credentials.conf(原 meta-scope.conf 改名降格:凭证要求表机器版)。

**第一性重推四件**(对"搬箱子"迁移方案的否决与替代):

1. **契约锁机制退役**(非"迁锁"):锁防的是拷贝漂移,单源+引用已消灭拷贝;contracts-locked.md 加退役注记转考古;残余真双端(规则文本↔hook 正则)以 fixture+审查守,如实声明。
2. **三段 pattern 不整体搬**:各审查 skill 自带模板;review-rules 只载维度选择表。
3. **skip 字段消亡**:豁免=微型 audit(同 frontmatter 文法,`verdict: exempt`+一行理由)——走凭证正道,对账天然认,消除"reconcile 不认 skip"的制度洞;豁免成本不变(3-5 行文件≈一行字段)。
4. **cross-ref hook 不扩边不分发**:互引断链=低频+审查可抓,降为可选工具箱件(随前缀消亡改名)。

**地图(硬要求)**:credentials-rules 的发现链五处同批——AGENTS×2(硬规矩行+对账命令,下游补第三条)/ M3(治理表单表化+分流机器拆除+开场规程命令)/ M4(治理表同步)/ QUICKREF+README / 上下文层现行版 spec 状态头注记。自检标准:任一入口 ≤3 步走到 credentials-rules。

**命名收敛**:check-meta-review.sh→check-audit-coverage.sh(分发)/ check-meta-cross-ref.sh→check-cross-ref.sh(工具箱)/ meta-scope.conf→credentials.conf(新增分发)/ 新 audit 命名 `audit-*.md`(工具 glob 双前缀兼容 meta-review-*.md)/ "meta-review"、"meta-L1~L4" 术语退役(Evidence Depth 字段名不动)。

## 不做(防 scope 扩散)

- 不动承重件:做审分离/二公设、bootstrap 4 维、audit+covers 文法与失效规则、开场对账、晋升门禁、书架登记、handoff 路径
- 不追溯改写历史(16 份 audit/旧 spec/旧 decision=考古层;双前缀 glob 保兼容)
- 不做细节交接/工作底稿(用户已拍"先治理后交接",另案)
- 不做渐进过渡(一步到位;双轨复杂度正是要删的东西)

## 残余风险(诚实声明)

- 三件套互引指针为新增同步面(低频、点状、可机核;触点完整性维+手工 cross-ref 工具守)
- 下游认知负担+1 文件名(地图行缓解);下游首次背 audit 制度(低频事件,credentials-rules 单入口可读)
- 改名期引用断链是"修一处漏同步"老病高发地形——spec 必须带消费点全枚举实数,计划逐处验证

## 追记(2026-06-13 spec 审阅轮,用户拍板二项 — 原文不删改,以本节为准)

- **凭证字段名全换**:`meta-review: true` → **`audit: true`**,含 21 份历史凭证**同批格式迁移**(仅 frontmatter 一行替换,covers 与正文零碰,git 历史保留原貌)。依据 = 用户立的解释:**immutable 保护的是内容,纯格式迁移不算改**(原话:"换,并且全换,我们不改内容,这个应该是格式问题,这样也不会出现两个章。")。工具回归单一解析路径,原"保留字段名"默认读法作废。边界:**文件名不换**(meta-review-*.md 留名,收集 glob 双前缀)——文件名被 decisions/ROADMAP/decision-trail/归档台账大量引用,改名即迫改 immutable 内容或制造死链,恰违"不改内容";字段是文件内部水管,无外部引用。防护:迁移前后各跑一次全窗对账留对照,欠账集合不得因迁移缩小(迁移刷新凭证 commit time,防掩蔽 stale 覆盖)。
- **check-meta-cross-ref.sh 删除**(原话:"删除"):不改名不保留,git rm(git 史可捞回)。互引守法全归审查「触点完整性维」+ 同批耦合纪律;`## meta-cross-ref: skipped` 字段随之彻底消亡;setup.sh 无需任何点名排除;原"改名保留+PAIRS 扩边"方案(第一性重推 4 的工具箱形态)作废。依据 = 第一性"机器值得存在=形式可判×高频/高损",两条均不满足。
- **收口工序适用(design-review 轮拍板)**:**方向评估全批适用,含治理批**(原话:"方向评估重要")——分工注记:治理审查核"这批合规达标"(以 decision/spec 为前提),方向评估问"方向本身对不对/该不该推翻"(连前提一起审),verdict 三路同构但站位不同,非重复;**安全扫描与流程审计治理批暂不纳入**(原话:"其他的我觉得可以暂时不用担心了"),维持 feature 侧——连带:①hook 脚本危险操作面/AI 指令文本注入面在治理批暂无机器扫,登记 ROADMAP 观察项(触发器:实战出险或用户重启);②exempt 滥用抽查改为 process-audit 按需/周期回看(不绑每批),covers 超 5 件必抽。治理批收口成本 = 凭证审查(2-5 fork)+方向评估(4 fork),用户知情接受。
