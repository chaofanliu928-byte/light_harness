# 活跃任务索引 — handoff 升格挂起任务线住处

- 日期:2026-06-20

- 类型:方案选择型
- 锁定 spec:`docs/superpowers/specs/2026-06-19-active-task-index-design.md`(brainstorm→system-design→自检→design-review×2→修订→code-review→凭证 audit verdict=pass)

## 问题

handoff 是单一台账(覆写+归档),只有一个「当前阶段/当前分支」字段,装不下并行/挂起的多条任务线。两个坏处:(a) 挂起的任务线(如"等真实项目某实案再捡起")在覆写蒸馏时易被整段抹掉——它不在"当前阶段",看着像废话就被砍;(b) 新窗口开场看不出"现在有几条活、哪些在跑、哪些挂着"。

## 用户原话(判断锚点)

- [01:07] "现在就升,但是怎么保证其一直活跃呢?以及怎么让ai可以一下就知道当前有几个任务?"
- [01:44]"b吧" / [02:10]"我说的是对齐强度是中还是重?"(锁定方案 B + 强度=中)

## 方案对比

| | A:锚 git 分支 | **B:人声明的任务线(采纳)** |
|---|---|---|
| 任务线定义 | = git 分支(地面真相,机器可对账) | 人声明,不锚 git,含未开分支探索线 |
| 保活硬度 | 强(git 撒不了谎) | 中(无地面真相,靠覆写重建+触发器+freshness) |
| 代价 | 只数"开了分支"的线 | 表达力广,保活靠机制非铁地基 |

**强度三档(轻/中/重)取「中」**:对齐现状台账对自身的强度(覆写重建+机器硬核+开场对账+freshness),不加码。「重」(每K次fork独立挑战者审挂起线)留档当"真出现僵尸线实证再升级"。

## 决定:方案 B + 强度中

**形态**:把 handoff `### 进行中/阻塞` 跨节升格为顶层 `## 活跃任务索引`(零新文件;落点=`## 目标`后、`## 进度`前)。机读表头 `活跃任务: N(进行中 X / 挂起 Y)`(开场一眼计数)+ 4 列二态表 `| 状态 | 任务 | 复活触发器 | 指针 |`(状态∈{进行中,挂起};挂起行复活触发器必填非空)。

**4 旋钮(用户拍板)**:① check-handoff `--reconcile` 机器核**最窄**(只核表头文法 + 挂起触发器非空,不核计数自洽/指针/不引模板占位文本,恒 exit 0)② 挂起软上限=5(软提醒,实战标定)③ 不做超期点名(留「重」升级)④ 触发器只机器核非空 + AI 语义自核(**删黑名单字面核**:design-review 两维独立判边际价值存疑+实现缺陷)。

**3 条诚实限度(显式留档不掩盖,spec §10.2)**:①③在场性同源(非两道独立闸)/ 僵尸线判断撞公设1(做事者自答,无独立眼睛,留「重」升级)/ 只部分规避 kb 击穿点5(局部持久层无独立闸)。
