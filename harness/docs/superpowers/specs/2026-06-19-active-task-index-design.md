# 活跃任务索引(active-task-index)系统设计

> 在 handoff 单一台账里**升格出一张「活跃任务索引」**:把现有的「### 进行中 / 阻塞」跨节升格为顶层 `## 活跃任务索引`(机读表头 + 二态表),让挂起的任务线不被覆写蒸馏掉、让 AI 开场一眼知道有几条活。
>
> brainstorming 拍板日期:2026-06-19(用户锁定输入:**方案 B = 人声明的任务线,不锚 git 分支,含未开分支的探索线** + **强度 = 中**)。
>
> 强度对照:现状台账对自身已是「中」(覆写重建 + 机器硬核 + 开场对账 + freshness),给索引卡选「中」= 把现有强度一致铺到新维度,**不加码**。

> **路径前缀约定**(双层仓,与 `drift-detection-design.md` / `design-context-delivery-design.md` 同约定,无歧义):
> - `docs/...` 一律指 harness 自仓库的 `harness/docs/...`;
> - `.claude/...` 一律指 `harness/.claude/...`;
> - 根级 `/AGENTS.md` = **仓库根**(`<root>/AGENTS.md`),区别于 `harness/templates/AGENTS.md`(M4 分发模板);
> - 分发下游同形**去 `harness/` 前缀**。

## 1. 需求摘要

> 直接流转自用户已锁定的需求清单(§1.5 列原文锚点),字段结构与 brainstorming 一致,不偷换不漏。

### 1.1 用户目标

handoff 是我每会话覆写的单一台账,但它只有一个「当前阶段 / 当前分支」,装不下我手头**并行或挂起的多条任务线**。结果两件事坏掉:(a) 一条挂起的任务线(比如"等真实项目出现某实案再捡起"那种)在下次覆写蒸馏时容易被整段抹掉——它不在"当前阶段",看着像废话就被砍了;(b) 我新窗口开场读 handoff,看不出"现在到底有几条活、哪些在跑、哪些挂着"。

我要的是:**在 handoff 里升格出一张「活跃任务索引」**——一行一条任务线,标清楚 {进行中 / 挂起}、是什么、挂起的话什么条件复活、本体料在哪。让挂起线有个**正式住处不被覆写吃掉**,让开场**一眼数清几条活**。

一句话:**handoff 顶部加一张机读的活跃任务索引表,二态 {进行中, 挂起},挂起行必填复活触发器;覆写时逐行重声明这条还活着吗,机器核只核两条结构事实(表头文法 + 挂起行触发器非空),触发器措辞质量靠 AI 语义自核,软,不阻断。**

### 1.2 核心场景(按优先级排序)

1. **[P0] 开场一眼知道有几条活**:谁(新窗口开场的调度者)→ 装载读 `docs/active/handoff.md` → 顶部 key:value 状态区之后即见 `## 活跃任务索引` + 机读表头 `活跃任务: N(进行中 X / 挂起 Y)` + 二态表 → 看到:N 条活的数目 + 每条 {状态 / 任务 / 复活触发器 / 指针},不必通读全文档反推。
2. **[P0] 挂起线不被覆写蒸馏掉**:谁(收口覆写 handoff 的调度者,走 `/structured-handoff`)→ ③覆写步**逐行重声明**「这条还活着吗」(不保留旧表整块,活的重写、挂起行当场重写复活触发器、完成移进度、放弃删行)→ 挂起线作为正式表行**留住**,不再因"不在当前阶段"被整段抹掉 → 看到:覆写后挂起线仍在表内,触发器是这次重新确认过的(非 copy 旧占位)。
3. **[P0] 机器核只核两条结构事实(进 `--reconcile` 范围最窄)**:谁(开场对账的调度者,手工跑 `check-handoff.sh --reconcile`)→ 机器核**只核与措辞无关的两条结构事实**:① 机读表头存在性 + 半角文法 ERE(命中全角走既有全角检测分支、按未做处理);② 挂起行复活触发器列非空(trim 后非空、非字面 `—`)→ **全软提醒、恒 exit 0、无 exit 2**(`--reconcile` 工具箱契约)→ 看到:一行状态结论(表头/触发器结构核过 or 点名哪行缺)。
4. **[P0] 复活触发器质量兜底(机器核非空 + AI 语义核,两层)**:谁(写挂起行的调度者)→ 切挂起必填触发器(无合法触发器不许标挂起)→ 机器侧核「非空」(切挂起却没写触发器即 stderr 点名);措辞质量最终靠 AI 覆写自核(纯主观无锚如"等时机"靠语义判)→ 看到:漏写触发器被机器逮到点名;措辞废话归 AI 语义核(公设1 限度,不声称机器保证质量)。
5. **[P1] 生命周期闭环(开启 / 进行中↔挂起 / 关闭)**:谁(会话内推进任务线的调度者)→ 三入口加行开启(新方向 / 口头探索线未开分支 / 从「下一步」提升)→ 进行中↔挂起切换(切挂起必填触发器)→ 关闭(完成:删行 + 成果进 `## 待晋升暂存` 走晋升门禁 + 一句话梗概进进度;弃置:删行,理由随归档件保全)→ 看到:任务线全生命周期都有正式动作,加行属正常会话内编辑(只有覆写整个 handoff 才走 `/structured-handoff`)。

### 1.3 边界与约束

- **做什么**:把 handoff.md 现有「### 进行中 / 阻塞」**跨节升格**为顶层 `## 活跃任务索引`(零新文件)+ 机读表头 `活跃任务: N(进行中 X / 挂起 Y)` + 4 列二态表 `| 状态 | 任务 | 复活触发器 | 指针 |`;改 3 文件:T1 单源模板字段集 / T2 SKILL 覆写步+自查步 / T3 check-handoff `--reconcile` 加约 10 行结构核段。
- **不做什么**(详 §10):
  - **不加 负责人 / 开始日期 / git分支列**(YAGNI:单人 dogfood / handoff 每会话覆写无保质期语义 freshness 已排除 handoff / 方案 B 不锚 git)。
  - **不做挂起线超期 X 天点名**(借 freshness-scout 读 handoff 违 freshness-rules 的 frontmatter-only + handoff 排除约定;改 `--reconcile` 的「无任何时间推断」硬契约成本高且 clone 后 mtime 不可靠;真要做留「重」升级)。
  - **不让机器核计数自洽**(N==X+Y / X==进行中行数 / Y==挂起行数 落 SKILL ④自查,AI 一眼可数,主责在自查不在 hook)。
  - **不让机器核指针 test-f / 不引用任何模板内部占位文本**(禁 grep `[待填]`/`[待更新]` 类死条件,防 kb-analysis 事实3 死条件漂移复发)。
  - **不重造晋升门禁**(完成行成果进 `## 待晋升暂存` 完全复用现有门禁)。
  - **不在 Stop 模式复制结构核**(自仓库 hook 不在场,Stop 模式加了白加;§3.1 注)。
- **挂起线软上限 = 5 条**:挂起行数 > 5 → stderr 软提醒「挂起线积压,考虑收编/弃置」,不阻断。初值显式标注**非实证最优、实战标定**(沿 freshness N=90 范式)。权威住址落 **structured-handoff SKILL**(改它命中 `.claude/skills/*` 而非 governance glob,与机制归属一致)。
- **性能/成本**:零运行时成本;check-handoff `--reconcile` 加约 10 行 grep/awk 结构核,毫秒级。
- **兼容性**:双层 harness 自仓库 + 单层下游分发都要能跑(check-handoff 既有双层探测复用,§3.1);半角纪律沿 check-handoff 全角检测同源(§4.3)。

### 1.5 已确认的决策(从需求对接阶段带入 — 用户锁定原文锚点)

- **方案 B(锁定)**:人声明的任务线,**不锚 git 分支**,含**未开分支的探索线**(未沉淀线指针写 `[未沉淀]`)。
- **强度 = 中(锁定)**:把现状台账对自身的「中」强度(覆写重建 + 机器硬核 + 开场对账 + freshness)一致铺到新维度,**不加码**。
- **落点(锁定)**:`### 进行中 / 阻塞`(`## 进度` 的子节)**跨节升格**为顶层 `## 活跃任务索引`,**零新文件**;精确位置 = **`## 目标` 之后、`## 进度`(抽离 `### 进行中`/`### 阻塞` 后只剩 `### 已完成`)之前**(brainstorming workflow 综合给的物理落点;此位置在 `## 待晋升暂存` 之前,天然规避 check-handoff `archive_staging_has_entries` 段边界,§4.1 注)。§1.5/§4.1/§8.1 三处统一以本落点为准。
- **状态二态 {进行中, 挂起}(锁定)**:旧「阻塞」并入「挂起」——「阻塞」token 已被 promotion 行的「阻塞(理由)」清账中间态占用(check-handoff GRAMMAR L119),复用会让机器核与读者双重混淆;「挂起」更准覆盖「未开分支探索线 / 等条件」。
- **表 4 列(锁定)**:`| 状态 | 任务 | 复活触发器 | 指针 |`;不加 负责人/开始日期/git分支(§1.3 YAGNI)。
- **机读表头(锁定)**:紧跟标题下一行 `活跃任务: N(进行中 X / 挂起 Y)`;严格半角 ERE;空账写 `活跃任务: 0(进行中 0 / 挂起 0)` 不写「无」;空表体留占位行。
- **4 旋钮(用户拍板锁定)**:① check-handoff 机器核落法 = 进 `--reconcile` 但范围最窄(只核表头存在性+文法 + 挂起行触发器非空,不核计数自洽/指针 test-f/禁引模板占位文本);② 挂起线软上限 = 5 条(软提醒不阻断,初值实战标定,权威住 SKILL);③ 挂起线超期 X 天点名 = 不做(留「重」升级);④ 复活触发器质量兜底 = **机器核非空 + AI 语义核(两层)**。
  > **旋钮④ 留痕(推翻旧决策须留痕)**:原拟「机器核非空 + 黑名单字面核 + AI 语义核」三层。「黑名单字面核」经 design-review 两维(方向盘对齐「中=不加码」+ 过度工程化「用户未要求 + 逮不到主目标 + 实现缺陷」)**独立**判边际价值存疑 + 实现缺陷(`grep -F '待定|以后|...'` 管道被当单一字面串、永不命中,死检查),**用户拍板删除**。机器侧只保留与措辞无关的「非空」结构事实;触发器措辞质量回归 AI 语义自核(诚实留档为公设1 限度,§4.4 / §10.2 限度#2)。
- **机制(锁定)**:覆写重建(防腐第①件,逐行重声明)落 SKILL ③覆写步;计数核落 SKILL ④自查;真实在场点 = 开场指令驱动手工跑 `--reconcile`(同既有 promotion 核在场前提)。

### 1.6 RUBRIC 风险标记

> harness 自仓库 RUBRIC 是空模板,真方向盘 = `CLAUDE.md` 核心原则 + 二公设代偿(沿 drift-scout / design-context-scout `rubric_mode='template'` 回落目标)。

- 涉及的惩罚项 / 红线:
  - **最小变更(核心规则 5)**:升格现有节(零新文件);check-handoff 只加结构核段不动既有分支;SKILL 只加覆写/自查两小步;每行 diff 可追溯。
  - **spec_gap_masking(feedback 戒条)**:**关键风险**——3 条诚实限度(①③在场性同源 / 僵尸线撞公设1 / 只部分规避 kb 击穿点5)是真缺口,须**显式写进 spec、不许措辞掩盖**(§7 + §10.2)。机器核非空**不许写成「触发器质量有机器保障」**(§4.4 + §10.2)。

### 1.7 业务规则(领域规则)

> 本机制的"领域"= handoff 台账的工作状态语义。把稳定领域约束单源写在这里。

- **规则1(二态互斥 + 触发器条件律)**:任务线状态 ∈ {进行中, 挂起};标「挂起」**当且仅当**有合法复活触发器(非空、且 AI 语义自核为可判复活条件)。进行中行触发器列恒为 `—`(不需要条件就能继续的活)。
- **规则2(职责五区不互相收纳)**:活跃任务索引 = **要干的活**(在做/挂起的任务线,**有工作状态**)/ `## 下一步` = **新窗口照此续作的待办指引**(给接手者的行动清单,**无状态机、不是任务线本身**)/ `## 待晋升暂存` = **干活的料**(知识条目,本会话出生待裁决)/ `## 指针` = **找料的图**(全局接手必读)/ `## 进度 > ### 已完成` = **收尾战果**。五者不互相收纳;**任务线专属本体指针进该行指针列,全局接手指针进 `## 指针`**。
  > **`## 活跃任务索引` vs `## 下一步` 边界(避免同一任务两处双记)**:活跃任务索引是「现存哪些活、各处什么状态」(任务线 + 状态);`## 下一步` 是「接手者下个动作怎么做」(行动指引)。一条任务线已进活跃任务索引,其推进动作写 `## 下一步` 不算双记(状态 vs 动作两个面);但**不得**把同一任务线作为「另一条待办」重复登记进 `## 下一步`(那是双记,致计数混淆)。从 `## 下一步` 提升为正式任务线见 §4.5 入口③。
- **规则3(覆写重建律)**:活跃任务索引在 `/structured-handoff` 覆写时**逐行重声明**(非整块保留),挂起行触发器当场重写(不许 copy 旧占位)。这是防腐第①件(逐行确认),与第②件(机器结构核)在自仓库**同源在场 = 非两道独立闸**(都靠开场跑 `--reconcile` + 遵从,开场没跑则一起静默缺位、共单点失效,非互为冗余备份;限度#1,§10.2)。
- **规则4(加行不是覆写)**:会话内开启/切状态/关闭任务线属**正常文档编辑**(直接改 handoff),**只有覆写整个 handoff 才走 `/structured-handoff`**。


## 4. 数据模型

> 本功能"数据" = 活跃任务索引表行结构(§4.1)+ 机读表头文法 ERE(§4.3)+ 生命周期状态机(§4.5)+ 精确版式样例(§4.2 消费契约样例)。

### 4.1 表行结构(消费契约;升格自 `### 进行中 / 阻塞`)

`## 活跃任务索引` 段结构(精确位置:**`## 目标` 之后、`## 进度`〈抽离 `### 进行中`/`### 阻塞` 后只剩 `### 已完成`〉之前**;此位置在 `## 待晋升暂存` 段之前,与 §1.5 落点 / §8.1 T1 改动同一物理落点):

```
## 活跃任务索引

活跃任务: N(进行中 X / 挂起 Y)          ← 机读表头(标题下一非空行)

| 状态 | 任务 | 复活触发器 | 指针 |
|---|---|---|---|
| <进行中|挂起> | <一句话名词/动作> | <— | 条件> | <-> 路径 — 为什么读 | — | [未沉淀]> |
```

> **段位置硬约束(规避 check-handoff `archive_staging_has_entries` 段边界)**:`## 活跃任务索引` 精确落在 `## 目标` 之后、`## 进度` 之前,**必在 `## 待晋升暂存` 之前**。check-handoff `archive_staging_has_entries`(L123-131)用 awk `/^## 待晋升暂存/` 起、`/^## /` 止扫暂存区——本段标题 `## 活跃任务索引` 也匹配 `^## `;只要它在暂存段**之前**(远离),就不会落进暂存区的 awk 扫描窗口被误读为暂存条目。实读 check-handoff.sh:123-131 确认该段边界逻辑。位置不只靠本口头硬约束:§3.1 ④自查加「活跃任务索引在 `## 待晋升暂存` 段之前」位置自查(cheap,AI 覆写时核),作为契约方执行。
>
> **新核② awk section 边界同源**:T3 核② 在 `## 活跃任务索引` 表体扫挂起行时,同样镜像本 archive_staging awk 范式——`^## 活跃任务索引` 开窗、遇下一个 `^## ` 关窗(§3.1 核②),只在本节内扫,不越界扫到 `## 进度`/`## 待晋升暂存` 等后续段的表格行。

每数据行(check-handoff awk 读 / SKILL 人读)理解为:

```text
TaskRow {
  status:   "进行中" | "挂起"      // 第 1 列;半角无修饰;二态(旧「阻塞」并入「挂起」)
  task:     string                 // 第 2 列;一句话名词/动作定位,不抄行号(行号随改动失效)
  trigger:  string                 // 第 3 列;进行中行="—";挂起行=必填非空(措辞质量靠 AI 语义自核)
  pointer:  string                 // 第 4 列;"-> 路径 — 为什么读" | "—" | 未沉淀线 "[未沉淀]"
}
```

- **空表体留占位行**:`| (无活跃任务) | | | |`(保留,使空账结构可见、防被读作"漏写")。占位行是**唯一特判**,但**不必额外特判逻辑**——它状态列(`(无活跃任务)`)非「挂起」,核②的「状态列==挂起」判据自然跳过,无须为占位行单写分支。
- check-handoff awk(`-F'|'`)跳过表头行(`| 状态 |`)、分隔行(`|---|`)、占位行——状态列(`$2` trim,即 trim 后第 1 个非空字段)判 `进行中`/`挂起` 才进触发器核(触发器=`$4`,第 3 数据列)。

### 4.2 数据流 + 精确版式样例(消费契约样例)

**非空账**(放进 spec 当 check-handoff/SKILL 双侧消费契约样例):

```
## 活跃任务索引

活跃任务: 3(进行中 2 / 挂起 1)

| 状态 | 任务 | 复活触发器 | 指针 |
|---|---|---|---|
```

### 4.3 机读表头文法 ERE(最关键 — 半角纪律,与 check-handoff 全角检测同源)

机读表头(紧跟 `## 活跃任务索引` 标题的下一非空行):

```
ERE(严格半角):  ^活跃任务: [0-9]+\(进行中 [0-9]+ / 挂起 [0-9]+\)$
空账:            活跃任务: 0(进行中 0 / 挂起 0)        ← 不写「无」
非空账示例:      活跃任务: 3(进行中 2 / 挂起 1)
```

- **半角纪律**(沿 check-handoff GRAMMAR L119 + 全角检测 L173/L352 同源):`: ( ) /` 全半角;中文 IME 默认全角,机读静默漏 — 命中全角走既有全角检测分支(grep -F '（' '）' '：')、stderr 提示「半角」、按未做处理。
- **表头是结构事实(措辞无关)**:check-handoff 核的是**数字位存在 + 文法**(`活跃任务: <数字>(进行中 <数字> / 挂起 <数字>)` 格式合规),**不是数目真**(N/X/Y 是否等于实际表体行数 = 语义事实,属"数目真")。**「过结构核」只意味着表头格式合法,不意味着 N 可信**;数目真(N==X+Y、X/Y==实际行数)由 ④自查核(AI 一眼可数,旋钮①),机器不核——避免"过结构核 = N 可信"的误解。
- 表头缺失 / 文法不命中(非全角)→ stderr 点名「机读表头缺失/文法不合」+ 按未做处理(恒 exit 0)。

### 4.4 复活触发器质量兜底(机器核非空 + AI 语义核,两层)

> 两层兜底,**职责分明**——spec **不许**把「机器核非空」表述成「触发器质量有机器保障」(§10.2 限度#2 戒条)。

| 层 | 落点 | 判据 | 逮什么 | 逮不到什么 |
|---|---|---|---|---|
| **机器核·非空** | T3 `--reconcile` + T2 ④自查 | 挂起行触发器列 trim 后非空、非字面 `—` | 切挂起却没写触发器 | 写了但是废话(措辞质量) |
| **AI 语义核** | T2 ③覆写自核 + ④自查(做事者自答) | 这是不是真复活条件 / 可判触发点 | 语义上的纯主观无锚(如"等时机"/"看情况") | **自答撞公设1**(限度#2) |

- **机器侧只认与措辞无关的「非空」结构事实**——逮「切挂起却漏写触发器」;**触发器措辞质量(写了但是废话)归 AI 语义自核**,机器不核。删黑名单留痕见 §1.5 旋钮④(design-review 两维独立判边际价值存疑 + 实现缺陷,用户拍板删)。
- **触发器质量最终仍靠 AI 覆写自核**——而 AI 自答是公设1 乐观偏差击穿点(§7 D6 + §10.2 限度#2),「中」强度下无独立眼睛盯。本设计**不声称机器能保证触发器质量、不声称已根除僵尸线**,挂「重」升级。

### 4.5 生命周期状态机(开启 / 进行中↔挂起 / 关闭)

```
                       ┌─────────────────────────────────────────┐
   [开启] ──────────►  │  进行中 (触发器=—)  ⇄  挂起 (触发器=必填)  │
   三入口:             └─────────────────────────────────────────┘
   ① 新方向                        │  切挂起:必填合法触发器
   ② 口头探索线未开分支              │         (无合法触发器不许标挂起)
      (指针=[未沉淀])               │  切进行中:触发器回 —
   ③ 从「下一步」提升                ▼
   初始 状态=进行中,触发器=—,    [关闭]
   指针=路径或[未沉淀]            完成:删行 + 成果进 ## 待晋升暂存(走晋升门禁)+ 一句话梗概进 ## 进度>### 已完成
                                  弃置:删行,理由随归档件保全
```

| 实体 | 从状态 | 触发事件 | 到状态 | 副作用 |
|------|-------|---------|-------|--------|
| 任务线 | (无) | 开启入口①新方向 / ②口头探索线未开分支 | 进行中 | 加行(状态=进行中/触发器=—/指针=路径或[未沉淀]);**正常会话内编辑,非 `/structured-handoff`** |
| 任务线 | (无) | 开启入口③ 从 `## 下一步` 提升 | 进行中 | 加行(同上)+ **从 `## 下一步` 删除被提升的那条**(避免同一任务两处双记,规则2 边界);若该待办仍需作为"动作指引"留 `## 下一步`,则二者关系 = 任务线在索引(有状态)、动作步在下一步(无状态),不重复登记任务本身 |
| 任务线 | 进行中 | 需等条件 | 挂起 | 填合法复活触发器(无合法触发器**不许**切挂起) |
| 任务线 | 挂起 | 条件满足/手动捡起 | 进行中 | 触发器列回 `—`(④自查加「进行中行触发器==—」核,防留旧触发器文本残留;§4.4 / §5.1) |
| 任务线 | 进行中/挂起 | 完成 | (删行) | 成果进 `## 待晋升暂存`(晋升门禁)+ 一句话梗概进 `## 进度 > ### 已完成` |
| 任务线 | 进行中/挂起 | 弃置 | (删行) | 理由随归档件保全(归档件①归档步已存) |

- **加行属正常文档编辑,只有覆写整个 handoff 才走 `/structured-handoff`**(规则4,§1.7)——避免"每加一条任务线就要走整套覆写门禁"的重量误解。
- 完成行**完全复用现有晋升门禁**(`## 待晋升暂存` 逐条裁决 + 路由表),不重造(YAGNI)。

## 5. 边界条件与错误处理

### 5.1 边界条件

| 场景 | 输入条件 | 期望行为 | 理由 |
|------|---------|---------|------|
| 空账 | 表体只有占位行 `\| (无活跃任务) \| \| \| \|` | 机读头写 `活跃任务: 0(进行中 0 / 挂起 0)`;check-handoff 核表头文法过、占位行不触发触发器核 | 空账=清白,非"漏写";不写「无」(沿 promotion 空账形范式) |
| 机读表头缺失 | 无 `## 活跃任务索引` 节 / 节下无机读头行 | check-handoff stderr「机读表头缺失」+ 按未做处理 + exit 0 | 软提醒不阻断(`--reconcile` 工具箱契约) |
| 表头全角污染 | 机读头含全角 `（）：` | check-handoff 走既有全角检测分支 stderr「半角」+ 按未做处理 + exit 0 | 中文 IME 默认全角机读静默漏(check-context-chain 教训,同 GRAMMAR L173) |
| 挂起行触发器空 | 状态=挂起但第 3 列 trim 后空 / 字面 `—` | check-handoff + ④自查 stderr 点名「挂起行触发器为空」 | 切挂起必填触发器(规则1);机器可逮「没写」 |
| 触发器措辞废话 | 触发器="等时机"/"看情况"等纯主观无锚 | 机器**不核措辞**,靠 ③覆写/④自查 AI 语义自核 | AI 自答撞公设1(限度#2,§10.2);机器只认非空,诚实声明(删黑名单后机器侧=非空,§1.5 旋钮④) |
| 挂起→进行中漏改触发器 | 切回进行中但第 3 列仍留旧触发器文本(非 `—`) | ④自查「进行中行触发器==—」核点出,改回 `—`(§4.5);机器侧不核(进行中行不进核②) | 防留旧触发器残留(`—` 一值两义:进行中合法填 `—`、挂起判非法空) |
| 计数不自洽 | N≠X+Y / X≠进行中行数 | ④自查 AI 一眼数出修正(机器核不管,旋钮①) | 计数自洽落自查(AI 一眼可数,主责在自查不在 hook) |
| 进行中行误填触发器 | 进行中行第 3 列非 `—` | ④自查提示改 `—`(进行中不需复活条件;非硬错) | 规则1 触发器条件律;软提醒 |
| 段位置错放(在暂存段后) | `## 活跃任务索引` 落在 `## 待晋升暂存` 之后 | 设计期硬约束规避(§4.1 注);若误放,占位/挂起行可能落进 archive_staging awk 窗 | 故 spec 钉死段必在暂存段前(§4.1 硬约束) |

### 5.2 错误传播路径

```
[机读表头缺失/文法不合] → [check-handoff stderr 点名 + 按未做处理] → [exit 0] → [AI 据点名修 live handoff]
[表头全角]             → [既有全角检测分支 stderr「半角」] → [exit 0] → [AI 改半角]
[挂起行触发器空]       → [check-handoff + ④自查 stderr 点名] → [exit 0] → [AI 重写触发器]
[计数不自洽]           → [④自查 AI 数出修正] → [无机器路径,旋钮①]
[触发器措辞废话]        → [机器不核措辞] → [③覆写/④自查 AI 语义自核] → [撞公设1,无独立闸,限度#2]
[挂起→进行中漏改触发器] → [④自查「进行中行触发器==—」核] → [改回 —] → [机器侧不核进行中行]
```

无吞错:结构事实错(表头/触发器)走 stderr 点名(显式可见,恒 exit 0);计数/语义错走 ④自查/③覆写(AI 在场);**没有静默丢弃**(除"全过→静默通过"——那是 `--reconcile` 既有安静风格,非吞错)。

### 10.2 3 条诚实限度(对抗审查硬要求 — 显式写进 spec,不许措辞掩盖)

1. **①③在场性同源**:防腐①(③覆写逐行确认)与③(check-handoff 机器结构核)在自仓库都靠「AI 开场跑 `--reconcile` + 遵从」(自仓库 hook 不在场,kb-analysis 事实1),**非两道独立闸**;机器侧真正独立的只有「表头文法 + 触发器非空」两个结构事实。spec **不许**把「手工对账能核到」表述成等同常驻硬核(同 promotion 既有残余风险)。
2. **僵尸线判断撞公设1**:「这条挂起线还活着吗 / 触发器是不是真条件」是做事者覆写时**自答**=公设1(做事与判断分开)乐观偏差的**已知击穿点**;「中」强度下**无独立眼睛**盯僵尸线。显式留档(**借 kb-analysis 缺口4 的留档体例**:诚实留档 + 真案例再啃 + 不据此造机制;注:kb 缺口4 自身的「唯一可机制化候选」指的是「判 0 不做」决策的对抗抽查,**非**本设计的僵尸线——此处只复用其体例,不挪用「唯一候选」标签,参 `docs/references/2026-06-18-knowledge-preference-rule-boundary.md` §5/§6 缺口4),挂「重」(每 K 次 fork 独立挑战者审挂起线)的升级触发条件 = **真出现僵尸线实证再升级**。**不包装成残余风险**。§4.4 已明确「机器核非空 ≠ 触发器质量保障」,不许措辞掩盖。
3. **只部分规避 kb 击穿点5**:挂起线被设计成**跨会话存活**=handoff 内的「**局部持久层**」,「覆写重建」对它是「逐行誊抄」非「清零」。故对 kb-analysis 击穿点5(追加式更持久故障面)应表述为「**部分规避**」——规避了**追加形态**(挂起线随覆写逐行重声明、非追加堆积),**未规避**「局部持久 + 无独立闸」内核(限度#2 同源)。**不**表述为「正面规避击穿点5」。

### 10.3 不做清单(MVP 边界)

- **不加 负责人/开始日期/git分支列**(YAGNI:单人 dogfood / handoff 无保质期 / 方案B不锚git)。
- **不做挂起线超期 X 天点名**(违 freshness 约定 + 破「无时间推断」硬契约 + clone mtime 不可靠;留「重」升级,D4)。
- **不让机器核计数自洽 / 指针 test-f / 引模板占位文本**(旋钮①;计数落④自查,引占位文本=死条件漂移复发源)。
- **不在 Stop 模式复制结构核**(自仓库 hook 不在场,加了白加)。
- **不重造晋升门禁**(完成行成果走现有门禁)。
- **表头 token 登记 credentials-rules §8 双写条目**(T1↔T3 结构双写对,§8.4;原「非强双写对、不进 §8」论证经 design-review M2 推翻)。
- **不声称机器核保证触发器质量 / 不声称根除僵尸线**(限度#2;降低非根除)。

### 10.4 残余风险(诚实声明,至少含)

- **①③在场性同源**:开场没跑对账则结构核静默缺位(同 promotion 既有残余风险,限度#1)。
- **僵尸线判断公设1击穿**:「中」强度无独立眼睛盯僵尸线(限度#2,留「重」升级)。
- **局部持久层无独立闸**:挂起线跨会话存活,无独立闸盯其是否仍有效(限度#2/#3 同源)。
- **触发器措辞质量无机器闸**:机器只核「非空」;废话触发器(如"看情况")机器不核措辞,靠 AI 语义自核(公设1 限度#2,§4.4/§10.2)。
- **计数漂移**:只改表不改头(N/X/Y 不同步)——靠④自查 AI 数,机器不核(旋钮①)。
- **live↔template 覆写自由度致漂移复发**:覆写是 AI 逐行重建,可能再漂(靠触点完整性维兜)。
- **无痕跳过**:开启不加行(该开任务线却没开)机器测不出(同"机器测不出没写的东西")。
- **X/上限初值无实证**:dogfood 验不到任务线腐烂率/挂起积压率(同 meta-L4 缺口),按「不可证不在 bootstrap 内讨论」+「实战推真实项目」接受。
