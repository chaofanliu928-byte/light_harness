## 1. 需求摘要

> 来源:调度者嵌入的需求确认清单(已锁定,唯一需求源)。字段结构与清单一致,无遗漏无偷换。

### 1.1 用户目标

建一个**模型无关的上下文/知识/交接层**:知识的组织让人和 AI 都能用、不腐烂、可机械治理。工作台(handoff)和书架(知识库)两层分开但立硬制度——**工作台上有价值的东西必须上架登记后才许覆写**。防遗忘靠设计出来的机制,不靠 AI 自觉。

### 1.2 核心场景(按优先级排序)

1. **[P0] 新会话冷启动**:新会话启动 → 注入机制把瘦身工作台台账(状态+指针)送进上下文 → AI 顺指针按需取书 → 不重读全库即可接手干活。
2. **[P0] 留痕落库即登记**:任何会话(含不走 finishing 的调研/留痕直提交)把调研/决策/参考写进书架 → **同一批动作里**完成目录卡登记(机制承载:同批耦合+落库软扫+覆写硬核三层组合,见 §2.3) → 下个会话从索引可找到。
3. **[P0] 收口晋升门禁**:收口/覆写工作台前 → 把工作台有价值内容上架(决策→decisions、经验→对应格、调研→references)并登记 → **然后才允许覆写工作台** → 覆写后台账只剩状态+指针+声明。
4. **[P1] 换运行时接手**:其他 agent 工具或纯人工 → 从运行时中立入口(AGENTS.md)找到地图 → 照纯文件约定读懂两层 → 手工跑校验脚本核账。
5. **[P1] 知识不腐**:文档与现实漂移时 → 校验机制发现并提示 → 过时留痕**标注不删改**。(本批机器检测件推后——发现环节由人工盘点+审查兜底,降级显式声明,边做边提升)

### 1.3 边界与约束

**做**:handoff 模板推倒重写(档位二完整版)、晋升门禁、登记通用规矩机制化、知识库九格七规则骨架、入口地图、AGENTS.md、偏好层入仓、纯 bugfix 批。

**不做**:
- 档位三(统一编号/总清单/数据库图谱)——SUPPLY 类总清单已被对抗审查击穿(analysis §二丙击穿点 1-7)
- 向量索引(业界一手证据:agentic search 优于 RAG 索引,literature-map:86-92)
- "每任务全量重读"式防遗忘(Cline 家族模式,token 代价高,opensource-map:48)
- 自仓库不建 `docs/context/`(2026-06-05 dogfood 边界不动)
- 自动晋升(蒸馏是判断活,AI 列选项人拍板)
- handoff 搬家/改名(85 处引用,零增益高风险——禁用清单)

**硬约束**:
- **模型无关 = 跨运行时/厂商**:地基纯文件 + 开放约定,约定自含可校验性(人可手工核);hook 仅为 Claude Code 增强层。
- **防遗忘机制四层谱**(每个"必须发生的动作"至少一层承载,从强到弱):①同批耦合(登记是动作自带最后一步)②机器闸(hook/校验脚本)③凭证制度(行为必须留结构化证据,锚点可查,"只写已阅读不算证据",空话格式可被机械抽查)④版本化兜底(覆写自动留痕可找回)。**纯纪律不算保障**。
- **两道闸分开命名分开落地**:「空白即未做」(形式闸:字段空白/缺失/[待填] 一律判未做,机器可查)+「没讨论清楚不放行」(实质闸:三态准入 通过/阻塞/受控假设+回收点;判定基准 = 关键问题是什么/讨论到什么程度/有无影响下游的未决点/下游能否照此干活;由 AI 判,凭证制度+对抗审查兜底;按松紧梯度用——探索期轻、收口与高风险严)。
- **双向契约**:每类产物声明输入侧(读哪些上游来源+轻量读取凭证)与输出侧(下游消费者是谁、需要什么形态)。
- **机制借用边界**:借 16 步技能的门禁/凭证/初值/分流思路,不借多层结构;机制只挂现有流程节点(落库、覆写前、收口、会话起点),不新增步骤或层级。
- **机制触发时点必须对齐问题发生时点**(落库当刻、覆写前),不能只挂收口(C6 三条实证全部发生在非收口的留痕直提交,analysis:23-26)。
- **C7 契约**:handoff 字段变更 = 四处同步,设计必须给同步方案(→ §7 决策 D3)。
- **meta 路(自仓库主路径)执法不得依赖 evaluation-result.md**(乙/丙击穿点 4/6 同根,analysis:70、87)。
- **注入经济**:80 行预算;渐进披露三级(地图→台账→目录卡+本体;层位以 I1 注入序为准)。
- **半角机读 token 纪律**(`[ ] : , ( ) ->` 全半角)。
- **每个新机制过反问**"不加它,原问题怎么解决?"——答得出就删(→ §7.2 逐件反问表)。

### 5.2 错误传播路径

```
文法/锚点不合(I4 检出) → exit 2 + stderr 具体哪条不合+怎么修 → Claude 收到引导,补清账/改声明
                                                              → 人(他运行时)手工跑同脚本看同 stderr
登记缺失(I5 检出) → stderr 软提醒(文件名列表) → 下次 Stop 仍提醒直到登记;覆写时若被引用升级为硬拦(I4)
SKILL 流程中断(写书架失败) → 中止覆写,台账原状,归档件已存 → 重跑幂等
hook 自身故障/依赖缺失 → 降级 exit 0 + stderr 一行 → 不阻断工作;真保证回落到 SKILL 流程+审查(软硬协同既有原则)
```

不吞错误:所有 exit 2 必带"哪一条+怎么修"的 stderr;降级必留一行可见痕迹。用户可见的错误信息全部是动作引导,不是技术堆栈。
