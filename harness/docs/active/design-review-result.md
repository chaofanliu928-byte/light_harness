## 综合(按 plan 维序)

### 方向盘对齐(地板)
- 🟢 RUBRIC 空模板,正确回落 CLAUDE.md 五原则 + 二公设,主体无偏离;§10.2 限度#2 对公设1 击穿点的诚实留档是**正面对齐项**(挑战者附 0 偏离检查清单留痕)。
- 🟡 **「中=不加码」与黑名单字面核存在张力**:现状台账「中」强度机器核只核结构文法,无"对内容措辞做近似判定"这类判据;§4.4 新引入的黑名单字面核是现状没有的一类。spec 未论证它算"铺平"还是"加码"。→ 与过度工程化维 F1 同源,见下方**用户决策**。

### 自洽性(地板)
- 🟡 **新 awk reader 的「表体」section-end 边界未定义**:既有 archive_staging 用 `/^## /` 关窗,新核②没声明等价判据 → 实现者可能漏写关窗、越界扫到后续段表格行。
- 🟡 **机读表头 framing 张力**:§4.3 称表头是"结构事实(措辞无关)",但 N/X/Y 的"数目真"是语义事实;机器只核数字位存在、不核数目真 → 读者易误解"过结构核=N 可信"。
- 🟡 **`—` 一值两义**:进行中行合法填 `—`、挂起行 `—` 判非法空;挂起→进行中切回时若漏改回 `—`(留旧触发器文本)无任何核捕捉(反向只软提醒)。
- 🟡 **段位置只钉「在暂存段前」,未相对 ##目标/##进度/##下一步 精确定位**:与"原地升格自 ##进度 子节"两处措辞指向不同物理落点。
- 🟢 核②报错引用"任务列摘要",未定义任务列为空时的退化(次要)。

### 契约一致性 / 触点完整性(动态加)
- 🟡🔧 **黑名单 grep -F + 管道 → 永不命中(真缺陷,已实测确认)**:`grep -F '待定|以后|...'` 下管道是字面字符,整串当一个字面串,单词永不命中;既有同源写法是 `grep -F -e '（' -e '）' ...`(check-handoff.sh:173 实测)。按 spec 逐字实现 = 死检查,场景4"机器逮到等时机"承诺落空。**必修。**
- 🟡 **机读表头 ERE 是 T1 token 在 T3 的硬编码副本 → §8.4「非强双写对」论证不成立**:ERE 含 `活跃任务/进行中/挂起` 字面 token,与既有 promotion GRAMMAR(被代码自称"三处同名同文法"、按双写对待、登记 credentials-rules §8)同构;却被论证成不进 §8。护栏比既有 promotion 更弱(无硬核计数 + 不进双写清单,纯靠每次审查记得核)。**应修:登记双写 或 诚实改写 §8.4。**
- 🟡 **段位置"硬约束"无契约方执行**:没有机器/自查核段顺序,覆写 AI 自由调段序无护栏;一旦活跃任务索引落到暂存段后且表体出现 `- ` 行,污染既有空账判定。
- 🟡 **T1 模板改动未交代 ##进度 抽离后剩余形态 + 精确落点未锁**(与自洽性段位置同源)。
- 🟢 T3「约 10 行」对功能(awk 切列+表头定位+全角分支+黑名单)偏乐观、停在散文级无 awk/grep 骨架样例,可验证性偏弱。

### 完整性(动态加)
- 🟡 **新表与既有 ≤80 行预算交互未覆盖**:SKILL ④自查 #1 要求 ≤80 行 + 砍序("先砍散文,指针/声明不砍");新表既非散文也非声明,落入砍序灰区,超限砍谁未定义。
- 🟡 **##活跃任务索引 vs ##下一步 职责边界未定义,场景5 入口③悬空**:§1.7 规则2 四区独缺 ##下一步;入口③"从下一步提升"未定义提升后下一步该条删/留 → 可能同一任务两处双记(计数虚高)或漏记。
- 🟢 "原地升格"措辞 vs 实际跨节抽离(###进行中是##进度子节)。
- 🟢 开场未跑 --reconcile 时可数性靠可能漂移的 N 兑现,§5.1 未把"读到漂移 N"与场景1 闭合。

### 过度工程化(动态加)
- 🟡 **F1:黑名单字面核是用户未要求的第三层抽象,且 spec 自认逮不到主目标**:用户两诉求(保活 + 一眼数清)未要求机器鉴别触发器措辞质量;黑名单只逮 5 个词、漏黑名单外废话("看情况""回头"),AI 语义自核已是末层兜底 → 反向追问有替代解。新增硬编码字面常量 = 新漂移源 + 虚假安全感。与"中/不加码"张力(同方向盘维)。
- 🟢 表头全角检测分支与既有 promotion 全角检测重复模式(字符集还对不齐:表头有 `/`)。
- 🟢 空表占位行 + awk 跳过特判,是为机读头 N=0 已表达的事实再加协调成本。
