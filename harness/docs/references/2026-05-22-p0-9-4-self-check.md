## A. 理念层 — 二公设 + 反向硬约束

### A1. 二公设是否被实际引用?

**预期**:在 design-review / evaluate / meta-review 审查中,挑战者或调度者明确引用 "Pathological Optimist" 或 "行动公设" 作为判断依据。

**验证**:
```bash
grep -r "Pathological Optimist\|行动公设" docs/audits/ docs/decisions/
```

**通过判据**:≥ 1 次实际引用出现在 audit / decision 文件

**失败信号**:

- 引用但用错语境(例如用公设支持"自审")

---

### A2. 反向硬约束是否被实际触发?

**预期**:有提议违反公设(让同 agent 既做又审 / 主张内省代替行动),调度者应"默认拒绝,不进入辩论"。

**验证**:
- 看 `decision-trail.md` / `handoff.md` 是否有"拒绝违反公设的提议"实例
- 看 `process-audit` 是否抓到 "违反但未被拒绝" 的实例

**通过判据**:
- ≥ 1 次反向规则被触发 + 拒绝成功(或合理情况下 0 次触发但 0 违反)

**失败信号**:
- 出现 "designer 自审通过" 等违反公设的实例,未触发拒绝

## B. 规则层 — synthesis-rules.md 事前/事后

### B1. 事前规则(prompt 构造中性化)是否被遵守?

**预期**:每次 fork 挑战者的 prompt **不含**:
- 支持调度者结论的额外证据(材料 selection 偏向)
- "调度者认为重要的"排序(材料 ordering 偏向)
- "显然 / 实际上 / 重点是 / 关键是" 等引导词(措辞偏向)

**验证**:
```bash
# 抽查最近 3-5 次 audit,看挑战者 prompt(若有 log)或综合产出
grep "显然\|实际上\|重点是\|关键是\|调度者认为" docs/audits/*.md
```

**通过判据**:抽查的 prompts **0 处** 含禁用引导词

**失败信号**:
- prompts 含禁用措辞
- 抽查发现挑战者结论高度一致(可能 prompt 偏向)

---

### B2. 事后规则(综合阶段 4 条)是否被遵守?

**预期**:综合 N 挑战者结论时:
1. 回到任务原意图(GateGuard 查意图机制提取的)
2. 回到本会话决策
3. 按 RUBRIC 维度判断,不按"听起来对"
4. 按 RUBRIC 维度顺序读,**不按 fork 顺序**

**验证**:
- 抽查最近 3 次综合阶段产出(主对话 turn 综合段)
- 看产出是否明确引用 RUBRIC 维度

**通过判据**:综合产出基于 RUBRIC + 上下文意图,而非"挑战者 X 写得详细"等主观依据

**失败信号**:
- 综合产出按 fork ID 顺序读
- 综合理由含 "挑战者 X 听起来对" / "挑战者多数同意 X" 等
