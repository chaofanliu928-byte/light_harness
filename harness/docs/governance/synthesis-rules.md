## 适用范围

调度者面对多挑战者的所有场景:

| 场景 | 挑战者数量 | 综合者 |
|---|---|---|
| design-review | 4(自洽 / 完整 / 合理 / RUBRIC) | 调度者(Claude) |
| evaluate | 4(RUBRIC / 架构 / 文档 / Slop) | 调度者(Claude) |
| meta-review | N(模态决定) | 调度者(Claude) |
| process-audit | 2(流程遵从 / 效果满意) | 调度者(Claude) |
| security-scan | 3(凭证 / 危险操作 / 注入混淆) | 调度者(Claude) |

**P2 阶段约束(P2 = codex 接入,明确计划阶段)** — 综合阶段全部保 Claude,不 swap codex。理由:Generator(实现)与 Evaluator(综合判断)角色异源是公设 1(Pathological Optimist)的直接推论;综合判断是聚合多挑战者结论的关键节点,需保持模型一致性以稳定基线。

## 事前规则 — 挑战者 prompt 构造中性化

调度者**构造给挑战者的 prompt** 时,prompt 本身不能带有调度者的倾向。Council 完整机制已剔除,本节是其轻量替代。

### 4 条硬规则

1. **材料 selection 中性** — 不主动塞支持自己结论的证据(例如不要附"另一个项目用类似方法成功"的引用)
2. **材料 ordering 中性** — 按客观顺序(文件路径 / 时间戳 / RUBRIC 维度)排,不按"调度者认为重要的"排
3. **措辞中性** — 不用"显然 / 实际上 / 重点是 / 关键是"这类引导词;不写"调度者认为 X 关键,要严查"
4. **调度者自检 + 抽检兜底**(2026-05-13 降级) — 调度者自检前 3 条;落地审查时由 meta-review / process-audit 抽检 prompt 中性度。**不引入"prompt 独立审核 fork"**(原方案会引入嵌套 fork,违反扁平架构;成本翻倍)

### Bad / Good 对照

| ❌ Bad | ✅ Good |
|---|---|
| "请审查这份设计。**关键问题包括 X、Y、Z**。完整文档如下..." | "请审查这份设计。完整文档如下。按 RUBRIC 4 维度独立评分。" |
| "**显然**核心方案是 A 路径。请审查 A 路径的实施细节。" | "方案候选 A 和 B 在文档中,请审查每个方案的可行性。" |
| "**调度者认为**这个 hook 设计很关键,需要严格检查。" | "审查 hook 设计是否符合 [明确的客观标准]。" |

## 事后规则 — 调度者综合阶段

调度者**综合多份挑战者结论**时,必须遵守:

### 1. 基于上下文意图综合

回到本任务最初的意图(GateGuard 查意图机制提取的),判断每个挑战者结论是否真正服务于这个意图。

**不要让挑战者的具体观点替代你对意图的理解**。挑战者只看到挑战者 prompt 里的局部信息,调度者掌握全局意图。

### 2. 基于上下文决策综合

综合时回顾本会话已经做过的决策(设计选择 / 角色分配 / 排除项),判断挑战者结论是否与已有决策**一致**或**合理偏离**。

合理偏离 = 挑战者基于客观证据指出已有决策的缺陷,有具体事实和逻辑支撑。
不合理偏离 = 挑战者主观判断与已有决策冲突,但无新事实。

### 3. 基于客观角度综合

用 **RUBRIC 维度**对照每个挑战者结论评判,**不按"哪个挑战者听起来对"评判**。

不允许的判断方式:
- ❌ "挑战者 1 写得更详细 → 接受"
- ❌ "挑战者 2 的措辞更自信 → 采纳"
- ❌ "多数挑战者都说 X → 默认 X 对"(从众的反面)

允许的判断方式:
- ✅ "挑战者 1 在 RUBRIC 自洽性维度提供了具体反例 → 接受这一点"
- ✅ "挑战者 2 在 RUBRIC 完整性维度指出 X 节缺失 → 验证后接受"

### 4. 避免先入为主

**读完所有挑战者结论后再下判断**。综合时按 **RUBRIC 维度固定顺序**(自洽 → 完整 → 合理 → 对齐 — design-review 场景为例)交叉读所有挑战者对该维度的意见,**不按 fork ID / 时间戳 / 完成顺序**。

不按 fork 顺序的理由:LLM 处理输入序列时存在系统性顺序敏感性 — 先读到的结论会成为后续解读的锚点,影响中立判断。harness 扁平 fork 设计本身就是为消除这种锚定,综合阶段需配套规则才能完整生效。

## 事前 + 事后规则的逻辑链

| 阶段 | 适用规则 | 目的 |
|---|---|---|
| **fork 之前**(构造 prompt) | 事前 4 条 | 调度者给挑战者的 prompt 不带倾向 |
| **fork 之后**(综合输出) | 事后 4 条 | 调度者读挑战者输出时不被锚定 |

**事前 + 事后**合起来管的是"调度者面对挑战者的完整行为流" — fork 之前不污染挑战者,fork 之后不被挑战者污染。

事后 4 条的细化逻辑:
- 规则 1 + 2 — **回归任务的根本**(意图 + 历史决策),防止挑战者具体观点替代调度者全局判断
- 规则 3 — **用客观维度评判**(RUBRIC),不是主观印象
- 规则 4 — **行为层防 anchoring**(读的顺序中性化)
